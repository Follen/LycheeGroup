## 确认的改进项

### 1. 密集列表自然峰值仍超预算

优先级高。冷列表 26.84 MB、已预热列表 20.91 MB 均超过现行 20,000,000 字节门槛。业务审查确认完整结果仍保留，详情缓存上限 64 队；冷读 1000 条结果的成员筛选需要 5000 次读取，缓存后重复筛选为零。不能通过截断结果或收窄合法数据规模达标。

冷列表的 320 次本地筛选／排序合计 2222.68ms、最大 9.702ms；320 次刷新／滚动请求合计 1774.58ms、最大 8.211ms。这些是指定入口的同步包含时间，批量更新另有延迟任务，不能相加作为全部业务 CPU。下一步应围绕完整原生快照与本地重复渲染分开归因，保留现有功能、动画和数据规模。

### 2. 单项配置写入复制未变化的迁移标记

[`Configuration.lua`](../../addon/LycheeGroup/Configuration.lua) 的 `Change`（约第 202 行）每次复制 `user`、`presets` 和 `imported`。首次打开寻队后，角色迁移标记从 66 增至 320；在关闭通知、预先准备写入参数的离线隔离实验中，同一单键写入由 **5.078 增至 17.078 KiB/次**，新增 **12 KiB/次**。只收缩标记表的反事实实验降至 0.985 KiB/次，直接支持复制成本归因。

建议按实际修改内容延迟复制迁移标记，保留事务与恢复合同。该发现是暂态分配，不是已确认的保存数据泄漏。单键 Snapshot 本身已经只比较目标键，两次 Snapshot 合计两个键，不需要重新改为全表比较。

### 3. 寻队字段更新同步隐藏的设置页

[`Appearance.lua`](../../addon/LycheeGroup/Appearance.lua) 第 347、366 行将所有 `settings.*` 变更归入设置页同步。寻队字段属于该前缀，但不由设置页控件显示。设置页创建后即使隐藏，50 次实际数值编辑仍额外触发 **50 次 `Sync`、1400 次 `Get`**；同一离线夹具中的分配由 **27.135 增至 37.669 KiB/次**，增加 **10.534 KiB/次**。

建议按设置页实际使用的字段过滤通知，并保留当前显示控件需要的更新。分配差含 UI 替身成本；本轮没有把这组离线时间称作游戏内耗时。普通 `UpdateFilters` 连续 100 次仍为零 `Set`、零 Snapshot、零 Schema 查询；稳定 `SavePrefs` 约 1.063 KiB/次，且不写用户覆盖。

### 4. 笔记大批量编解码存在同步停顿成本

[`Transfer.lua`](../../addon/LycheeGroup_UI/Transfer.lua) 的 Encode／Decode 处理 1000 条记录、每条 198 字节备注加序号时，生成 481,719 字节文本；三轮编码 **106.61–109.52ms**，解码 **105.08–120.60ms**。数量、名称、备注往返一致，未写入保存笔记。

这是当前版本的实测大批量成本，未建立旧版同场景 CPU 对照，不判为本次提交引入的回退。后续若处理导入／导出停顿，可按解析与编码阶段拆分工作，同时测完成延迟与单批耗时。

### 5. 共享库的小额新增开销

[`Motion.lua`](../../addon/LycheeGroup/Libs/LycheeUI/Motion.lua) 第 268–272 行先读取并创建颜色起点表，再判断是否立即应用。减少动态效果开启时，离线 10,000 次操作相对旧版增加 10,000 次 `GetVertexColor` 和 937.5 KiB，即 **96 字节/次**；两版均无动画任务。可把立即写入分支移到起点读取之前。

[`Components.lua`](../../addon/LycheeGroup/Libs/LycheeUI/Components.lua) 的 `SetIconState` 增加声明所有权查询。私有原生 Context 中，普通未声明图标旧／新各测 500 次，均值由 **2.692µs 增至 7.951µs**，增量约 **5.259µs/次**；p95 从 3.5µs 增至 10.4µs。两者最终颜色一致，均每次读取一次颜色、透明度和去色状态，零 setter；离线稳定重复分配为零。该结果说明普通路径的 Lua 查询成本增加，没有证据支持把它归为主要列表内存原因。

固定声明颜色加 Apply 的当前路径稳定重复零 setter、离线零表垃圾；旧方法每次覆盖颜色后再修复。原生对照仅在同一私有 Context 替换旧 `SetIconState`，两者都使用当前 Styles；旧方法最终 alpha 为 1，当前为 0.72。因此保留计数和耗时，不把它当作完整旧库、语义相同的性能对比。

业务审查覆盖 Search 取消、Results 延迟任务、Floating、Tooltip、Application 租约与 GuideStop；12 个针对性模块通过 6921 项主 runner 断言，Guide 另有 26798 项内部检查。完整 1000 条结果未截断，64 队详情缓存有上限。共享库用持久存储模拟纹理，100 个颜色任务执行 10,000 帧没有帧级表分配；StopAll 后任务、有效缓冲和 OnUpdate 全部清空。

共享库还有旧版即存在的公共 API 缺口：[`Elements.lua`](../../addon/LycheeGroup/Libs/LycheeUI/Elements.lua) 释放 element 后保留空 scope 组。1000 个不同临时 table scope 释放后保留约 201 KiB，旧、新两版一致。当前产品全部传固定字符串 scope，临时 Tooltip／lease 对象是 owner，因此不将这项写成当前产品的持续增长。

私有原生布局沿用固定 24 个子项、16 个场景、各 300 次的现有探针，计时和调用计数分开。最高 p95 **0.3426ms**、最大单次 **0.7444ms**；flex 行／列稳定重排 p95 **0.0506／0.0504ms**，均零几何写入、零文字测量。首次创建和最大同步批次均为 **9.4514ms**，所有既定门槛通过，原生对象高水位保持 27。这里只测当前库的两种布局模式，不是旧提交与新提交的对照。
