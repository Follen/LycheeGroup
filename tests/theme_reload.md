# 主题重载与 main 等价验证

本说明维护 Theme／Configuration／Appearance API v2 的验证方法；该接口已随 1.2.4 发布。产品合同见 [API.md](../API.md)，开发边界见 [Development.md](../Development.md)。当前结果、实机数据与预算结论写入 [perfermance.md](../perfermance.md)。

`group` 的关系索引回归另覆盖 1,000 人公会与 500 名战网好友：相同姓名／GUID 不推进内容版本或通知界面，名单与账号换序、重复身份和无关资料变化保持稳定；真实身份、来源及成员资格变化仍更新。同步读取不吞掉待发通知，最后消费者退出取消任务；停用后名单清空再启用时，尚未移除的申请者记录会清掉旧关系标记。

Plus 功能整合的专项入口为 `lua tests/runner.lua group season_scores season_picker player_links find_enhancements activity_labels applicant_time floating`。覆盖身份四态循环、右键清除、旧组合保留、同职业同职责／嗜血筛选、未知数据与缓存失效、角色分类偏好、成绩服务的事件与关闭清理、一级分类反复切换不搜索、难度草稿取消旧请求及关闭恢复、确认活动只提交一次、选择器滚动复用和双语多字号下固定 44 行高内名称、成绩徽章与复选框的留位、URL 编码与未知服务器、当前成员复制和返回、标题语义色与实时刷新、活动显示别名与原始数据隔离、列宽及各类行高。全部模块已纳入完整 runner。原始贡献包用于行为参考，正式实现归现有业务所有者；客户端实际成绩与复制交互另行实机核对。

`tests/live_plus_features.lua` 是已连接客户端的真实数据探针，使用 `opaque` 策略、执行预算 120 秒，探针自身异步上限 105 秒。前提是非战斗、真实 Find 已打开并已有稳定的赛季钥石结果，且没有 Preview、模态窗口或已打开的菜单／Tooltip。它检查活动显示名与原始字段隔离、基础行高／标题颜色／最小队长列宽，以原生成员信息独立核对两个新筛选，再逐地图比较赛季成绩的两个原生 API 返回值、检查关菜单退订，并从真实当前玩家详情展开 IO 就地复制，核对当前身份、链接、焦点及关闭后的清理。原生值缺失如实记录，前提不足或断言失败明确报告未覆盖／失败。仅使用控制器与 `Button:Click`，不代表硬件操作；不改 Blizzard API、设置或笔记，不发送申请、邀请、取消和招募动作。结束、失败和取消时恢复原 Find 偏好引用、运行态筛选、列表位置、页面显隐及关闭的菜单／Tooltip 状态。

`tests/live_plus_preview.lua` 使用内置 Preview 的模拟申请者，检查原生 Frame 上的用时文字、五档颜色与 Tooltip，并用公开样式 `SetState` 核对浮窗取消图标的正常、悬停和恢复状态。另以原生 Glyph 验证颜色读取、19×15 自定义尺寸、内部纹理随 Frame 填充、`$parent` 的实际中心偏移和释放还原。使用 `opaque` 策略、执行预算 25 秒，探针异步上限 20 秒；要求非战斗且没有真实招募或活动申请，业务变化会中止。它不模拟鼠标命中，不把样例成绩记为真实申请者记录；结束后退出 Preview 并恢复原页面显隐。

`lua tests/runner.lua glyph_slots floating` 使用严格的 Frame 替身检查公开图标槽：原生 Frame 不提供文字或纹理颜色 getter，颜色由内部 Texture 读写，尺寸与 `$parent` 仍以 Frame 为对象；覆盖自定义颜色、尺寸、锚点、状态和行复用。LycheeUI 源库的 `tests/glyph_style.lua` 单独验证同一通用合同，不依赖产品模块。

浮窗布局更新由 `floating`、`data_broker` 和布局 runner 的 `floating_pool` 覆盖：半透明总背景及自定义 Theme 颜色、悬停恢复、活动标题和原生邀请边界、处理后空态与计时清理、同组成员各自的评分／装等，以及中英文 70%／100%／130% 字号下的文字与列间留位。`tests/live_floating_redesign.lua` 使用当前真实申请或招募快照，通过公开浮窗接口检查原生 Frame、状态点贴图、活动与队伍标题字号、领队与倒计时的间距及可见成员数值，并调用 `Screenshot()` 留图，收到截图成功事件后再恢复弹层。要求非战斗、未开启 `/lg floattest`，使用 `opaque` 策略和至少 8 秒预算；临时弹层检查最多保护输入 4 秒，结束恢复此前弹层显隐与宿主，清理任务和临时锚点。该探针不提交申请、邀请、拒绝或招募操作，也不把控制器调用记为硬件操作；实际覆盖状态以每次报告为准。[2026-10-24 验证记录](results/floating-redesign-2026-10-24.json) 区分移除时钟前的真实招募／申请场景和最终版本的空态检查。

`lua tests/runner.lua raid_groups roster_drag group` 覆盖当前成员装等缓存、团队换组原生动作边界及 Tooltip 拖动控制器：GUID 重新解析、团长／助理权限、自身和相关成员战斗、满组与交换、未知身份、成员离队、点击抑制、空小队落点与隐藏清理，并检查双语多字号提示布局。

`tests/live_raid_roster.lua` 要求非战斗且当前存在真实团队，没有 Preview、模态窗口、活动拖动或其他来源的 Tooltip；已有当前队伍分组名单时保存并恢复它。使用 `opaque` 策略、执行预算 20 秒，探针异步上限 15 秒；读取真实成员与已有装等，检查原生文字高度、三种落点的只读判断、拾取前后名单与成员几何稳定、跟随卡片缩放与鼠标穿透，以及取消后的任务和事件释放。已有招募与收藏时，另核对应用保持禁用、结束招募提示及占位已移除，并恢复收藏展开状态。三种战斗原因仅用于明确的提示展示检查，验证标题下方布局、重复替换、手动关闭和 4 秒自动关闭，不表示成员实际进入了战斗。探针不调用换组动作，结束恢复原页面与原有名单浮层；真实鼠标投放与服务器换队结果仍需单独记录。

`tests/live_roster_layout.lua` 用于当前没有团队时的原生布局检查，要求非战斗、主窗已创建，没有活动菜单、模态窗口或拖动。使用 `opaque` 策略、执行预算 20 秒，异步上限 15 秒；将明确标注的 11 个本地样例成员按 5／5／1 分入三个小队，核对标题内距、成员间距、同行小队背景高度、短小队空白、拾取缩放、鼠标穿透及取消清理。它仅调用 Tooltip 视觉控制器，不切换页面、不改原生 API 或真实名单，业务服务仍拒绝样例换队；结束恢复原浮层并检查页面、显隐和搜索代次未变。该结果只计为原生 Frame 与动画验证，不计为真实团队权限、鼠标投放或服务器换队通过。

`tests/live_menu_geometry.lua` 在独立 LycheeUI 上下文检查原生菜单：80 像素实例行、零高折叠、初始选中行、第 100 项的定位和滚动，以及勾选／禁用项折叠后的重开恢复，共用有界行池。要求 r38 及非战斗，使用 `observation` 策略和 10 秒预算；同步完成后关闭菜单、捕获层和父级，清空动效。它不修改玩家主题或业务数据；诊断对象在本次运行中创建，因此安排在产品内存测量之后。公开主题进入真实关系菜单、导入待重载及值回调另由 `theme_menu` 回归覆盖。

`node tests/check_architecture.cjs` 验证内置 LycheeUI 的冻结清单与 SHA-256，检查共享源码的产品依赖和业务文件的加载归属；传入独立 LycheeUI 目录可同时核对源库。`test_product_components.lua` 检查共享库、Context 与控件工厂没有产品方法或状态所有者，包含页面和提示的延迟构建；该脚本已纳入布局 runner。

布局 runner 中的 `test_applicant_hover.lua` 通过实际申请者行与 Tooltip 回调重放 A→相邻行 B→WCL 的路径，检查左右弹出及不同缩放时仍复制 A、停在 B 后切换，以及离开、隐藏、裁切和关闭后的任务清理。另以正常动画和减少动画两种设置检查申请者邀请／拒绝按钮的首次悬停、按下、松开、移出和隐藏复用，核对语义色与透明度且不触发组队动作。坐标与悬停状态由离线替身提供；游戏内鼠标命中需另行验证。

## 离线入口

在产品仓库根目录使用 Lua 5.1 和 Node.js：

```powershell
lua tests/runner.lua
lua tests/run_layout_checks.lua
node tests/check_architecture.cjs
lua tests/test_live_theme_memory.lua
lua tests/test_live_refresh_memory.lua
lua tests/test_live_relations_memory.lua
lua tests/test_live_heroic_memory.lua
lua tests/test_live_list_memory.lua
lua tests/test_live_memory_scenarios.lua
lua tests/test_live_compare.lua
lua tests/test_live_ui_probes.lua
lua tests/ui_preview.lua
node tests/compare_main_ui.cjs
lua tests/measure_configuration.lua
lua tests/measure_creation.lua
```

产品 runner 包含 core、configuration、appearance、theme_reload、brand_motion 及原业务、输入、表格和界面测试。`test_brand_motion.lua` 按 1ms 步进将两种尺寸的品牌轨迹与独立二分参考对照，并检查取消、批量停止、改尺寸及首帧时长；通用任务的结束和清理合同由共享库测试维护。布局 runner 包含字号、成员尺寸、产品组件、页面布局、静态元素、迟建对象、实例复用、浮窗池和结果行读取。`test_result_row_details.lua` 通过实际 Results getter 与 Find／Tooltip 消费链验证团本列表按需摘要、非首位队长、进度未知与零值、完整悬停详情及五人头像。它们验证真实 Lua 控制器与替身对象，不证明游戏受保护调用或鼠标命中。

`test_theme_reload.lua` 重新创建会话并复用保存数据，覆盖导入后已有和迟建对象保持当前来源、重载后统一生效、幂等导入、账号／角色选择、旧混合包迁移、静态覆盖清除、无效定义回退与错误保留。真实初始化顺序包含主包 ADDON_LOADED、第三方导入、PLAYER_LOGIN 和浮窗创建；关窗再开不作为重载。

`lua tests/runner.lua group` 另覆盖明确取消前的状态核对：游戏状态已更新而本地仍是提交中时可正常取消，真实 pending、邀请、已结束和不存在的申请不误提交，重复操作不重复取消，其他申请及成员数据不被补读。回归同时走真实浮窗“取消全部申请”按钮和 Applications 服务；它证明旧状态误拦截的修复，不解释玩家现场最初提交没有反应的原因。

1.2.4 发布后的审计回归可用 `lua tests/runner.lua minimap group ui resize` 单独执行：小地图复用启动解析表；申请者成功种族资料复用、缺失后恢复和中立阵营变化；Find 离页后偏好刷新、关闭动画与快速重开；笔记在错误或保存后重新新增／编辑，以及原生空文字返回 `nil` 时的反馈空间。完整入口仍包含这些模块。该轮默认界面对照使用发布提交 `23bbdb24b5ad475534bb786a339c1874264d13a0`；历史架构改造的固定 main 参照继续保留。结果见 [审计记录](results/audit-1.2.4-2026-10-24.json)。

后续申请者详情的两条用时由 `group`、`ui` 和 `test_font_layout.lua` 覆盖：当前与最佳记录的独立限时、完整分秒、超时、缺失回退、最佳副本同名冲突、成功资料复用和暂缺后重试，以及双语 70%／100%／130% 字号下的时间列留位与长副本名换行。

用时颜色在 `ui` 中覆盖未限时灰色、剩余 3%／5%／10% 分界的两侧、满限时与超时、复用行重新着色；只在左侧用时添加色码，右侧限时和分隔符保持次要文字色，分档依据原始时长而非四舍五入后的文字。`lua tests/runner.lua core native_queue` 验证原生绿眼睛提前／延后加载、已有招募、申请与排本并存、纯排本左键保留原生队列菜单、已结束申请、右键菜单、重复点击、模拟退出和打开失败恢复。native_queue 使用固定游戏源码的点击分支替身，不提交真实申请或排队，不代替实机受保护调用检查。

`test_element_refresh.lua` 现验证固定主题及导入待生效，保留字体／尺寸实时行为。`test_element_layout.lua`、`test_find_elements.lua` 和池测试在 fixture 第四个参数预载主题，保留静态 slot、状态、锚点、实例换键与列表几何。热主题事务、逐叶 diff 刷新次数、任意撤回和方法包装器断言已随取消的接口移除。原生输入所有权及归还快照仍保留验证。

测量脚本使用离线 Lua 堆和替身对象，读数不能换算为 WoW 四包字节。停止或强制 GC 的诊断测量单列，不用于自然峰值达标结论。

产品专项测量留在本目录，默认使用内置 LycheeUI：`measure_font_cost.lua` 检查字体切换成本，`measure_element_values.lua` 检查元素值读取，`measure_theme_context.lua` 检查新 Context 解析成本，`measure_static_allocations.lua` 分开首次建页与预热后的切页／字号成本。后者的 `stable`、`native` 模式减少 Lua 替身实现产生的额外开销，`native cow` 只在诊断虚拟机内比较静态规则共享方案，不修改运行文件。历史调查见 [static-allocation-2026-10-23.md](results/static-allocation-2026-10-23.md)。

2026-10-24 的界面调整另由 `test_find_filter_layout.lua` 和 `test_notes_layout.lua` 验证，均已加入布局 runner。前者覆盖中英文、70%–130% 公开字号与 160% 压力场景、最小窗口、同组快捷控件在主界面与弹窗间迁移、分类切换、完整文字、滚动裁切与命中恢复、值保留及对象复用；另通过真实结果通知检查固定鼠标命中资格，覆盖溢出二次测量、空结果集和分类迁移，不允许普通刷新临时禁用鼠标；后者覆盖页头工具栏、两行记录、类型与日期留白、编辑区反馈避让和历史图标居中。浮窗主入口的打开、关闭和动画中反向归 `test_floating.lua`。产品 runner 的 `test_applicant_time.lua` 覆盖分数／实际用时切换、默认无提示、单行时间提示、数值排序、裸名刷新、池行迁移、申请和成员复用、离页清理、裁切和对象复用；原生用时读取、活动地图匹配、限时缓存及未知值在 `test_group.lua` 验证。客户端可用内置申请者预览检查文案与字体，模拟成绩不能记作真实申请者数据证据。

寻队单行活动列由 `test_table_find.lua`、`test_ui.lua`、`test_font_layout.lua` 和 `test_find_pool.lua` 覆盖：12 条目录路由、活动列图标与表头起点、队长姓名后的关系／笔记标记、正文 19 号字及 53／44 基础行高、活动显示名与原始目录的隔离、结果和申请的池行复用、旧列宽拆分及保存重载，以及团队职责／总人数原位替换且不重排列表。活动表头的三态、目录顺序、未知活动、目录失效与排序保存由 `test_table_find.lua` 验证；默认与各表头排序中的好友／公会优先结合 `test_group.lua` 验证。申请名额提示与行高由 `test_application_notice_layout.lua` 沿真实 Applications 状态通知验证：五项满额、取消／拒绝释放名额、绿色提示、关闭、样式重应用与字号变化；普通行保持基础高度，被拒绝行的提示完整，出现位置与最终布局一致。设置分类由 `test_settings_sections.lua` 检查八组内容、保存范围、切页清理、语言／主题重载、双语 70%／100%／130% 和最小窗口，已加入布局 runner。屏蔽页由 `test_blocked_layout.lua` 检查标题／数量／清空同行、表头与正文对齐、双语多字号、窄窗口及名单池复用；业务移除和清空继续由 `test_ui.lua` 覆盖。字体专项检查中英文 70%／100%／130%、未知评分、分钟／小时／天数、两位职责数、拒绝提示底行、主区左右边界及外侧滚动槽；离线布局不代替游戏中的文字裁切和图标呈现检查。

以下入口补充分配来源与读取时机的离线诊断：

```powershell
lua tests/measure_ui_firstbuild.lua
lua tests/measure_ui_cycles.lua
lua tests/measure_ui_cycles.lua profile
lua tests/trace_find_row_reads.lua
```

`measure_ui_firstbuild.lua` 按页面、设置分区和隐藏分支统计首次构建的替身对象及 Lua 堆净变化。`measure_ui_cycles.lua` 在预热后进行 12 轮切页和字号往返，记录对象、字体、规则与布局数量；`pages`、`fonts` 分别只切页或只调整字号，`profile` 临时包装调用并报告排除子调用后的堆净变化。这两个脚本采用自然 GC，堆差可以为负，不能当作累计分配量。`trace_find_row_reads.lua` 用 105 条模拟团本记录追踪首入、可见字号变化、隐藏字号变化及重进页面的成员统计读取，输出调用路径、实际绑定数和可见数；它检查读取范围，不建立游戏性能结论。这些脚本只修改自身进程内的 fixture。

## 验证范围与通过条件

| 场景 | 必须保留的行为 |
| --- | --- |
| 已有与迟建对象 | 主窗、浮窗创建后导入并选择主题，当前颜色、字体、材质、尺寸和业务状态保持不变；随后创建的页面、菜单、Tooltip、弹窗、原生输入及新池行仍使用本次启动主题。 |
| 重载与存储 | 保存并重载后，所有对象使用同一新主题；再次导入相同 ID／revision／内容幂等。账号／角色选择、显式默认、升级、移除和覆盖清除按 API 的优先级确定下次启动来源。验证结束恢复原选择、主题存储及实时偏好并再次重载核对。 |

## 实机与清理

自然连续场景使用 `live_theme_memory.lua`。它要求当前 LycheeUI r46、API v2 已加载、非战斗、没有 Preview 或活动模态窗口；有招募时观察真实招募与申请者，没有招募时等待实际非空搜索结果。最多等待 12 次初始搜索检查，随后遍历包含鸣谢页的 9 个设置分区及 12 轮四页／字号切换，基本操作间隔 0.75 秒。每轮重进寻队再检查搜索完成、结果代次及可见行填充，未完成时以 0.5 秒间隔最多等 12 次；失败明确记为未覆盖，不以空列表成本算通过。异步上限 120 秒。使用原生 Button:Click 调用入口，不代表硬件点击。日志记录操作边界和等待样本、观察器刷新成本、同一时刻四包字节数、每轮实际结果规模和 `budgetPassed`，`report.ok` 不能代替预算字段。

在已连接的同一项目执行一次固定请求，并按 CLI 返回的原操作继续：

```powershell
lycheedev live execute --project . --session <CON-id> --file tests/live_theme_memory.lua --request theme-cold-natural-01 --budget-seconds 120 --wait-seconds 45 --policy opaque --format json
```

探针会暂时修改会话字号、动效偏好和页面状态，因此使用 `opaque` 策略，未完成时沿用原请求恢复。结束、报错、取消时恢复原值、原页面、各页显隐和导航状态，取消自有 timer；浮窗可见状态在主窗还原后恢复，避免被主窗关闭再次收起。账号／角色存储及已有招募身份必须保持不变。`test_live_theme_memory.lua` 使用真实产品 fixture 检查完成、取消、观察器报错、首次开页后局部 UI 引用尚未赋值时的失败与迟到回调，假计数不用于内存结论。`mainBuiltAtStart` 区分本轮是否覆盖主窗首次创建；已经打开的主窗不能记作冷路径。

寻队页会在正常进入时保存角色筛选。探针在首次进入前隔离 `Group.prefs.find`，结束、取消或失败后恢复原引用和原运行态筛选，重置页面读取标记；恢复 Core Configuration 三层不代替这项检查。生命周期测试使用真实 Find／Search 控制器，分别检查角色筛选内容、原引用和运行态恢复。

沿用 [live_memory.md](live_memory.md) 的 LycheeDev 连接、返回验证和清理方法。主题改造的自然场景必须计入登录、首开、四页、正常动画、字号与缩放往返、浮窗、原生输入，以及实际存在的搜索、招募和申请者；已有玩家业务不为测试前提而取消。

Theme 的 pending 测试先保存账号／角色主题与偏好，对导入、迟建对象、字号隔离及重载分别采样；完成后通过明确恢复数据和重载还原。保留固定请求、实际客户端与角色身份、每包同一时刻的字节数、采样规模、业务结果和 cleanup。四包预算按性能文档执行，不通过强制 GC、清空存档、删结果、缩小池容量或关闭正常动画达标。

DataBroker 适配由产品 runner 的 `test_data_broker.lua` 覆盖，可单独运行 `lua tests/runner.lua data_broker floating`。检查双语状态、可选库延迟加载、独立浮窗关闭后的摘要及悬停列表更新、点击入口、动画结束、多个 Broker 按钮与原宿主的所有权切换，以及后台订阅释放；使用真实荔枝控制器和标准库替身。Ellesmere 的字体、图标裁切及实际栏位显示在游戏内检查。
